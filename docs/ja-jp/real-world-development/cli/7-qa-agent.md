`quality-checks` スキルで自動チェックを実行し、Playwright MCP を使ってブラウザーでフィルタリングを確認しました。次に、明確な QA プロセスを持つカスタム エージェントにこれらの機能をまとめます。

このレッスンでは、次の操作を行います。

- カスタム エージェントが指示、スキル、MCP ツールと連携する方法を確認します。
- 再利用可能な品質保証プロファイルを作成して確認します。
- QA エージェントを選択し、フィルタリング issue に照らして結果をレビューします。

## シナリオ

pull request (PR) を開く前に、Tailspin Toys では要件、コード品質、自動チェック、テスト カバレッジ、ブラウザーでの動作を一貫してレビューしたいと考えています。カスタム エージェントを使うと、QA プロセスを調整し、再利用可能なレポートを作成できます。

## カスタム エージェントとは

カスタム エージェントは、Markdown プロファイルで定義する Copilot の専門的なバージョンです。プロファイルには、エージェントの目的、指示、利用可能なツールを記述します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

これまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの指示はチームの標準を記述します。`quality-checks` スキルは繰り返し実行できるチェックをまとめます。Playwright MCP はブラウザー ツールを提供します。QA プロファイルは、要件の評価と結果の報告に、これらの機能をどう使うかを Copilot に伝えます。ほかの機能を置き換えるものではなく、別の会話も必要ありません。

## QA プロファイルを作成する

機能の PR を開く前に、Copilot に再利用可能な QA プロファイルを作成してもらいます。プロファイルでは、QA が行うチェックと守るべき境界の両方を定義します。

1. Codespace に戻り、フィルタリングの会話が Interactive モードであることを確認します。
2. 既定のエージェントにカスタム エージェントの作成を依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタム エージェントを作成してください。機能を issue と合意済みの要件に照らして確認し、リポジトリの指示に従い、quality-checks スキルを実行し、Playwright MCP で動作を検証し、カバレッジが不足している場合はテストを追加してください。

   各要件について、根拠を示しながら合格、失敗、またはブロックとして報告してください。実装コードを変更する前には必ず確認を求め、変更をコミットしたり pull request を開いたりしてはいけません。

   まずはレビュー用にプロファイルだけを作成してください。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、プロファイルをレビューして、意図した QA ワークフローと境界が Copilot に伝わっていることを確認します。これにより、検証だけを行う予定なのに、不完全または範囲の広すぎるエージェントが機能を変更するのを防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. frontmatter を確認します。`description` は必須です。`name` は省略可能ですが、設定するとエージェントの表示名が明確になります。
3. プロファイルの指示を読み、QA が要件から始め、リポジトリの指示に従い、`quality-checks` スキルを実行し、Playwright MCP を使うことを確認します。
4. QA が根拠を示し、実装コードを変更する前に確認を求め、変更をコミットしたり pull request を開いたりしないことを確認します。
5. これらの責任や境界が欠けている場合は、続行する前に既定のエージェントへ修正を依頼します。

## issue に対して QA を実行する

Copilot CLI は会話の開始時にプロジェクト エージェントを読み込みます。プロファイルを作成したら同じフィルタリングの会話を再開し、QA を選択します。これにより、issue と計画の判断をコンテキストに含められます。

1. 次のプロンプトでエージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 作成したばかりのエージェントは、使用可能なエージェントの一覧にまだ表示されない場合があります。その場合でも、上記のコマンドで有効にできます。

2. QA エージェントに機能のレビューを依頼します。

   ```plaintext
   issue と計画で決めた内容に照らして、フィルタリング機能をレビューしてください。PR を作成できる状態ですか?
   ```

3. QA エージェントが作業を開始します。
4. 完了したらレポートを確認します。

- QA エージェントを選択し、フィルタリング issue に照らして結果をレビューしました。
